# 进度定位说明

已知歌曲时长时，进度条支持点击或拖动。拖动期间显示预览时间、歌词和进度，松手后只提交一次；确认结束前保留预览，随后读取真实播放状态。暂停时定位成功会自动恢复播放，已自动播放的播放器不再重复发送播放命令。取消拖动、切歌、上翻聊天或关闭插件会取消未提交的手势。

进度条可通过 Tab 聚焦：左右方向键每次调整 5 秒，Home / End 定位到起点或终点。未知时长、演示模式或控制正在处理时不发送新定位命令。未播放部分保持灰色。

## 命令和确认

0.3.19 的渲染器通过现有 `configure({seek:{positionMs,expectedKey}})` 桥传递位置和捕获的歌曲身份，无需重新安装应用内加载器。旧的 `control('seek', positionMs)` 入口仍兼容。主进程先校验主渲染器来源、插件启用状态、数值范围（0–86,400,000 毫秒）和身份结构，再读取会话核对来源、完整标题、歌手、专辑和时长。歌曲已变则返回失败，不发送定位。确认身份后，将位置钳制到歌曲时长。

原生适配器优先通过本地播放路由发送 `SeekToPlaybackPosition`（24），选项 `PlaybackPosition` 使用秒；本地路由不可用时使用全局命令入口。主进程将刚读取的原始标题、歌手、专辑和时长传给助手，助手发送前再次核对，验证中也检查播放器及歌曲身份。切歌则停止确认，不继续控制新歌曲；需要恢复播放时，也携带原身份做发送前检查。发送后约 150 毫秒开始轮询，2.5 秒内播放头到达目标 ±2.5 秒才算成功。单个 helper 的主进程超时为 4.5 秒。

成功后刷新时间轴基线，避免暂停时的旧进度或尚未返回的快照覆盖新位置。播放器仍暂停时，再发送播放命令并确认状态。失败时恢复真实进度；整首歌词打开时在浮层内提示，否则打开设置显示“定位失败，请在 QQ 音乐中操作”。

## 整首歌词

点击歌词条或键盘聚焦后按 Enter / Space 打开整首歌词浮层。当前行高亮并自动居中，仅滚动歌词容器，不滚动聊天。滚轮、触摸滑动、滚动条操作或滚动按键暂停跟随，可点“回到当前歌词”恢复。浮层按可用视口空间放置在歌词条上方或下方；小窗口内限制尺寸。

每行使用原生按钮，可点击或用键盘激活。定位目标为 `line.start + lyric.offset`，与显示时 `position - offset` 的规则一致；负数归零，达到/超过歌曲终点的行不允许点击。必须有同一 songmid 的歌词和歌曲身份，未知时长、演示模式、拖动/定位/播放控制处理中不发命令。

歌词文档变化后重新建立行按钮；旧按钮闭包核对完整文档及歌曲身份，不能向新歌发出旧时间。换歌重置跟随状态；没有歌词、插件关闭或歌词条隐藏时收起浮层。Escape、关闭按钮或点击外部也可收起；Escape 和关闭按钮将焦点归还歌词入口。歌词内容仅通过 textContent 写入。

## 诊断和验证

原生适配器保留 `ZCODE_MUSIC_SEEK_MODE=route|send|elapsed` 和 `ZCODE_MUSIC_SEEK_VERIFY=0` 供本地排查。默认采用 route → send，并启用结果验证；`elapsed` 不参与默认流程。诊断定位会真实改变播放位置。

- `test/seek.test.mjs` 检查预览、单次提交、取消、切歌和失败恢复。
- `test/control.test.mjs` 检查 IPC 校验、时长钳制、播放器过滤、定位后自动播放和时间轴基线重置。
- `test/seek.html` 检查真实界面的拖动、键盘操作、灰色剩余进度、演示模式和失败提示。
- `test/full-lyrics.test.mjs` 在不联网的 DOM 测试中检查行高亮、手动滚动、恢复跟随、旧行拒绝、演示/忙碌禁用与安全文本；纯函数测试覆盖偏移方向、歌曲身份和视口布局。
- `test/full-lyrics.html` 提供完整交互预览及浏览器内检查按钮，使用模拟播放器，不操作真实 QQ 音乐。
- `npm run test:control -- <适配器目录>` 会短暂暂停、播放和定位 QQ 音乐，通过独立进程读取结果，并恢复初始播放状态和对应原进度；检测到切歌后停止恢复旧歌曲的位置。
