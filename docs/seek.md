# 进度定位说明

已知歌曲时长时，进度条支持点击或拖动。拖动期间显示预览时间、歌词和进度，松手后只提交一次；确认结束前保留预览，随后读取真实播放状态。暂停时定位成功会自动恢复播放，已自动播放的播放器不再重复发送播放命令。取消拖动、切歌、上翻聊天或关闭插件会取消未提交的手势。

进度条可通过 Tab 聚焦：左右方向键每次调整 5 秒，Home / End 定位到起点或终点。未知时长、演示模式或控制正在处理时不发送新定位命令。未播放部分保持灰色。

## 命令和确认

固定桥接接口仍使用 `control('seek', positionMs)`，无需重新安装应用内加载器。主进程先校验主渲染器来源、插件启用状态和数值范围（0–86,400,000 毫秒），再读取目标会话并将位置钳制到歌曲时长。

原生适配器优先通过本地播放路由发送 `SeekToPlaybackPosition`（24），选项 `PlaybackPosition` 使用秒；本地路由不可用时使用全局命令入口。发送前和验证中检查播放器身份，验证中切歌则停止确认，不继续控制新歌曲。发送后约 150 毫秒开始轮询，2.5 秒内播放头到达目标 ±2.5 秒才算成功。单个 helper 的主进程超时为 4.5 秒。

成功后刷新时间轴基线，避免暂停时的旧进度或尚未返回的快照覆盖新位置。播放器仍暂停时，再发送播放命令并确认状态。失败时恢复真实进度并打开设置显示“定位失败，请在 QQ 音乐中操作”。

## 诊断和验证

原生适配器保留 `ZCODE_MUSIC_SEEK_MODE=route|send|elapsed` 和 `ZCODE_MUSIC_SEEK_VERIFY=0` 供本地排查。默认采用 route → send，并启用结果验证；`elapsed` 不参与默认流程。诊断定位会真实改变播放位置。

- `test/seek.test.mjs` 检查预览、单次提交、取消、切歌和失败恢复。
- `test/control.test.mjs` 检查 IPC 校验、时长钳制、播放器过滤、定位后自动播放和时间轴基线重置。
- `test/seek.html` 检查真实界面的拖动、键盘操作、灰色剩余进度、演示模式和失败提示。
- `npm run test:control -- <适配器目录>` 会短暂暂停、播放和定位 QQ 音乐，通过独立进程读取结果，并恢复初始播放状态和对应原进度；检测到切歌后停止恢复旧歌曲的位置。
