# 副歌标记

进度条只显示一个 3×5 像素的圆角竖标，位置为副歌起始毫秒数除以歌曲总时长。标记跟随当前主题色或专辑色，未播放部分仍为灰色。标记不拦截鼠标事件，点击、拖动和键盘定位继续使用原有进度条行为。

## 数据与选择

匹配歌曲后，向 QQ 音乐网关 `https://u.y.qq.com/cgi-bin/musicu.fcg` 请求 `music.mir.MirInfo / GetRefrain`，参数为 `songMidList: [songmid]`。只发送歌曲标识，不使用播放器登录信息。

响应的 `req.data.refrain[songmid]` 是 JSON 字符串，其中 `chorus_seg_times` 使用 `起始毫秒,结束毫秒|...` 表示副歌段，`cfd_funclevel` 表示置信度。低于 0.5、格式无效、起止顺序错误的段不参与选择。

只取置信度最高的一段；相同置信度取最早的有效起点。当前接口提供的是整首歌共用的置信度，因此同一响应的多段副歌会选最早起点。起点须位于歌曲时长内；未知时长、接口失败或无有效数据时隐藏标记。

## 加载与缓存

请求在后台执行，不等待副歌数据才返回歌词。每首歌的并发请求合并，有效数据缓存 6 小时，空结果和失败缓存 5 分钟，最多缓存 300 首。请求超时为 6 秒。

播放快照仅携带选中的一个副歌点及歌曲标识，界面再次核对歌曲和时长。切歌后不会沿用上一首歌的标记，迟到的响应只更新所属歌曲的缓存。数据就绪后随下一次播放轮询显示。

## 验证

`test/refrain.test.mjs` 覆盖响应解析、置信度门槛、最高分与同分选择、无效时间、异步缓存、切歌隔离，以及没有歌词时仍可显示副歌点。`test/refrain.html` 使用本地模拟数据检查单点显示、主题/专辑配色、灰色底轨和进度定位。
